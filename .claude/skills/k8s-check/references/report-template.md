# Report Template — k8s-check

This template defines the canonical structure for the final consolidated report.
Populate every section from the discovery file data. Omit sections that have no
findings only if the section is conditional (e.g. "Issues by Severity" sections).

## Status emoji key

| Status | Emoji | Meaning |
|--------|-------|---------|
| HEALTHY | 🟢 | All checks in this area passed |
| DEGRADED | 🟡 | Warnings detected; functionality may be reduced |
| CRITICAL | 🔴 | Critical issue detected; action required |
| OK | ✅ | Individual component is healthy |
| WARN | ⚠️ | Individual component has a warning |
| CRIT | 🔴 | Individual component has a critical issue |
| INFO | ℹ️ | Informational note, no action needed |

## Severity mapping

Each sub-skill assigns severities to its findings:
- **CRIT** — Component is down, failed, or blocked; immediate action needed.
- **WARN** — Component is degraded, near threshold, or at risk; action recommended.
- **INFO** — Notable observation; no action required.

The overall status is derived as: worst severity present across all findings.
